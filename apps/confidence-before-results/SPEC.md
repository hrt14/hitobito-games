# 結果が出る前に自信をつくる — SPEC

## Exact use moment
新しい挑戦、提案、発表、営業、公開などを前にして、「実績がない」「失敗したら評価が下がる」「もっと準備してから」「自分よりできる人がいる」と考え、動きが弱くなりそうな瞬間。

## Central benefit
成功の証拠を待ってから自信を持つのではなく、「成功する保証はなくても、次の一手は出せる」という前提を先に入れ、10分以内の具体的な行動を開始する。

## Problem / design rationale
自信を「成功後の感情」にすると、最初の行動に必要な自信が永遠に不足しやすい。一方で「絶対成功する」と思い込ませる設計は、準備・確認・リスク管理を弱めるおそれがある。そのため本ゲームでは、自信の対象を結果ではなく行動・修正・継続に限定する。

## Core interaction
1. 今止まりそうな挑戦を選ぶ／入力する。
2. 自信を止めているブレーキを4種類から選ぶ。
3. 「結果→自信」ではなく「自信→行動→修正→結果」へ順番を反転する。
4. 自信ゲージを3回タップして「次の一手は出せる」を身体操作で確定する。
5. 10分以内に始められる一手を選ぶ／入力する。
6. 3・2・1のカウントダウン後、現実で行動する。
7. 戻って「一手を出した」を押すと+1勝。壁に当たった場合は一手選択へ戻る。
8. 次の挑戦でも同じループを反復する。

## First 10 seconds
- 画面最上部で「結果 → 自信 / 順番を逆にする」を提示する。
- タイトル「結果が出る前に、自信をつくる。」を大きく表示する。
- 「成功する確信ではなく、次の一手を出せる前提」と明記する。
- 最初の操作は「今、何を前にして止まりそう？」への選択だけにする。

## Success condition
1ラウンドの勝利条件は、挑戦そのものの成功ではなく「選んだ次の一手を現実で実行した」こと。完了すると通算「先払い成功」が+1される。

## Uniqueness
- ポジティブな言葉を読むだけでなく、自信の対象を「結果」から「行動」に限定している。
- 3タップの先払い操作と3・2・1カウントダウンで、認知の切り替えを身体操作へ変換する。
- 壁に当たったときは失敗扱いにせず、その場で次の一手を再選択する。
- 成功結果ではなく「行動したこと」をスコア化する。

## Repeat-use strategy
- 新しい挑戦・壁・不安が出るたび1ラウンド60秒程度で再利用できる。
- localStorageに通算勝利数を保存し、「結果より先に動いた回数」を積み上げる。
- 「壁に当たった」ボタンから同じ挑戦の次の一手を即座に再選択できる。

## Audience
挑戦の前に自分を疑いやすい人、準備や実績を待ちすぎて初動が遅くなる人、失敗評価や他人比較で行動が弱くなる人。

## UI / screens
- Challenge: 挑戦選択／自由入力。
- Brake: 自信のブレーキ4択。
- Switch: 順番反転、自信ゲージ3タップ。
- Action: 10分以内の一手4択／自由入力。
- Countdown: 3・2・1・GO。
- Real world check: 実行／壁／未着手の分岐。
- Result: +1勝、通算回数、共有、再戦。

## Copy rules
- 「絶対成功する」「成功は確定」など、結果を保証する文言は使わない。
- 自信は「次の一手を出す」「修正する」「続ける」能力に向ける。
- 失敗や壁はスコア減点にせず、再選択のトリガーとして扱う。

## Data / privacy
外部通信なし。localStorageに通算勝利数、最終実行日時、前回の挑戦と一手のみ保存する。共有はユーザー操作時のみWeb Share APIまたはクリップボードを利用する。

## Constraints
- 外部API・外部ライブラリ・広告・課金なし。
- モバイル片手操作を優先する。
- prefers-reduced-motionに対応する。
- 重要な判断で必要な確認・専門家助言を省略させない注意書きを置く。

## Acceptance criteria
- 初見10秒以内に「結果を待たず、行動の自信を先に入れるゲーム」と理解できる。
- 選択しないと次へ進めない。
- 自信ゲージは3回の操作が必要。
- カウントダウン後に現実行動チェックへ進める。
- 「壁に当たった」で一手選択へ戻れる。
- 完了で通算勝利が+1され、再読み込み後も保持される。
- 結果を共有できる。
- 360px級モバイル幅でも主要操作が読めて押せる。
