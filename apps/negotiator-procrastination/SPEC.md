# NEGOTIATOR｜先延ばしをやめろ — Product Spec

## Exact use moment
やるべき仕事・勉強・家事があるのに「時間がない」「気分が乗らない」「何から始めればいいか分からない」「ちゃんとやれないなら始めたくない」と抵抗して先延ばししている人が、スマホで2分以内に交渉され、対象へ30秒だけ着手する。

## Central benefit
「やる気が出るまで待つ」状態を終わらせ、今この場で最小の着手を1回起こす。

## Problem / design rationale
先延ばし中は、大きい要求ほど拒否しやすく、強い命令ほど「今は無理」という抵抗も起きやすい。このアプリは、最初に大きめの要求を提示して拒否を受け止め、その後は要求を小さくする、本人に選択権を返す、小さなYESを積み上げる、最後に具体的な開始行動へ落とす、という交渉構造を使う。

設計根拠として、以下の既存研究を参照する。
- Freedman & Fraser (1966), foot-in-the-door: 小さな依頼への承諾後に、より大きな依頼への承諾が増える条件を検討した古典研究。
- Cialdini et al. (1975), door-in-the-face: 大きな依頼を断られた後に依頼を小さくする rejection-then-moderation 手続きを検討した研究。
- Gollwitzer (1999), implementation intentions: 行動を具体的な状況と結びつける if-then 型の計画に関するレビュー。
- Psychological reactance literature: 選択の自由を脅かす言い方は抵抗を生みやすく、選択を残す表現は反発を抑える方向で研究されている。

これは「必ず効く心理操作」をうたうアプリではなく、本人が自分自身の先延ばしに対して使う行動開始ツールとして実装する。

## Core interaction
画面上のNEGOTIATORが要求を出し、ユーザーは毎回3択から返答する。基本は「やる」1択と、「まだ無理」を表す異なる理由2択。拒否理由に応じて次の要求サイズと文脈が変わる。

交渉が進むほど、画面上の要求メーターが 25分 → 5分 → 60秒 → 30秒 → 10秒 と物理的に縮む。ユーザーは単に正解を選ぶのではなく、自分の抵抗理由を選ぶことで交渉条件そのものを変える。

最後は「対象を開く／道具を手に取る／最初の1操作をする」などの具体的な着手を選び、30秒の実行タイマーを開始する。タイマー終了前でも「始めた」を押せる。

## First 10 seconds
最初の画面に「先延ばし中？ 25分やれますか。」と大きく表示し、すぐ3択を押せる。長い説明や診断は置かない。タイトル、現在の要求時間、NEGOTIATORの発言、返答3択だけで「断っても交渉が続くアプリ」だと理解できる。

## Success condition
ユーザーが最終的に「今やる最小行動」を1つ選び、30秒タイマーを開始し、「始めた」を押すか30秒を走り切ること。結果画面では、最初に拒否した要求と最終的に実行できた要求サイズの差、および今回最も強かった抵抗理由を表示する。

## Uniqueness
既存の `ato-5min` や `3sec-action` が「タスクを小さくする／即決する」トレーニングなのに対し、このアプリはユーザー自身の拒否を入力として、アプリ側が譲歩・選択権・小さなYESを使いながらリアルタイムに要求を再交渉し、実際の着手まで連れていく会話体験である。

## Repeat-use strategy
ローカルにセッション回数、着手成功回数、最頻抵抗タイプを保存する。再訪時は前回までの傾向を表示し、2回目以降は「あなたは長時間要求で止まりやすい」など、最初から小さい要求へ寄せる。毎回先延ばし対象は違っても、交渉パターンが適応するため再利用価値がある。

## Title rationale
- Main user benefit/motive: 時間を節約し、先延ばしから今すぐ着手へ移る。
- Why this title is direct and specific: シリーズ名 `NEGOTIATOR` と目的「先延ばしをやめろ」をそのまま示す。
- How it matches the actual app: アプリがユーザーの拒否と実際に交渉し、要求を小さくして着手へ導く。
- Market/uniqueness checks actually performed (if any): タイトルはユーザー指定。外部市場での商標・Amazon重複調査は今回未実施。
