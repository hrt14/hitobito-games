# 『死ぬまでに、あと100ターン』仕様書

## 1. 一言
残りターン数が常に見えている人生ゲーム。何をしても1ターン減り、1周目の終盤で初めて捨てた「どうでもいいこと」を、2周目では100ターン目から捨てられるかを体験する。

## 2. 狙い
有限性を知識として説明せず、ゲーム内で実際に100個の残り時間を失わせる。訓練対象は「死を意識すること」ではなく、有限な時間の前で、自分にとって重要でない反応を早く手放す反射。

## 3. コア体験
- 画面上部に常時「残り 100」。
- 選択するたび必ず -1 ターン。
- 10秒迷うと自動で1ターン消費し「迷っているうちに終わった」と記録。
- 75 / 50 / 25 / 10 / 3で強制的に残りターンを意識させる。
- 100ターン終了後、同じ100場面を同じ順番で2周目に入る。
- 2周目では各場面に「前回選んだ選択肢」を表示する。
- 最後に1周目と2周目の配分変化を比較する。

## 4. 勝敗
単一の正解・高得点は作らない。仕事、家族、休息、挑戦などの価値観をゲーム側が順位づけしない。

比較対象は主に以下。
- 自分で意識して選んだターン
- 人の目で使ったターン
- 迷いで使ったターン
- 惰性で使ったターン
- 人・物語・休息に使ったターン
- 2周目で前回と変えたターン数

## 5. シナリオ設計
25種類の人生場面から、各10ターン×10フェーズ＝100場面を決定論的に生成する。1周目と2周目は完全に同じデッキを利用する。

シナリオ例：
- 仕事と約束の時間
- しばらく話していない人
- 休日と疲労
- 気になるイベント
- 乗り気でない誘い
- 起きていない失敗への不安
- 旅行の「いつか」
- 謝りたいこと
- 60点の挑戦
- 同年代との比較
- 家族との10分
- 体の違和感
- 学びたいこと
- 頼まれごと
- 子どもの頃の好きなこと
- 環境を変えるか
- 朝の余白
- 会議での意見
- 崩れた予定
- 手放せないもの

## 6. 重要ルール
### 6.1 行動そのものを善悪化しない
「残業＝悪」「家族＝正解」にはしない。同じ残業でも「自分で仕上げたい」と「評価が怖い」を別の選択として扱う。

### 6.2 1ターンの値段は最後まで同じ
残り100でも残り1でも、1回の選択は1ターン。終盤だけ特別に価値が高くなる数値補正は入れない。

### 6.3 説明ではなく画面で有限性を感じさせる
残数を最大の視覚要素にする。選択ごとにカウントをアニメーションし、ライフラインを物理的に短くする。

## 7. UI
- ダーク背景。
- 画面中央上に巨大な残りターン。
- その下に1本のライフライン。
- 1場面1カード、選択肢は3つ。
- 下部に「余白 / つながり / 物語 / 体力」を補助表示。
- 残り10以下は背景とカウンターを赤系へ変化。
- 2周目は青系の周回バッジで識別。

## 8. 2周目の差分体験
2周目では正解を教えない。前回の自分の選択だけをゴースト表示する。

最終比較：
- 前回と違う選択をした数
- 迷い・人の目・惰性の合計
- 意図的に選んだ合計
- 最後の10ターンで意図的に選んだ数

最終質問：

> 残り10になって捨てたものを、残り100のときから捨てられましたか？

## 9. 想定プレイ時間
1周3〜6分、2周合計6〜12分。10秒無操作でターンが進むため停止し続けることはない。タブが非表示の間は公平性のためタイマー停止。

## 10. 技術
- 静的HTML / CSS / Vanilla JS
- 外部ライブラリなし
- スマホファースト
- localStorageには2周目終了時の比較結果のみ保存
- GitHub Pages/Vercelなど静的ホスティングでそのまま配信可能

## 11. 完了条件
- 100ターンが正常に最後まで進む。
- 放置時もターンが減る。
- 1周目と2周目で同じシナリオ順になる。
- 前回選択が2周目に表示される。
- 2周目終了後に比較結果が表示される。
- iPhone幅で横スクロールしない。
- 主要ボタンが44px前後以上のタップ領域を持つ。
- JS構文エラーがない。
- 初見10秒以内に「残りターンを使って選ぶゲーム」と理解できる。
