# 大きく出る。 — Product Spec

## Exact use moment
提案・お願い・目標・値段交渉などを言葉にする直前、「迷惑にならないように」「断られないように」「身の丈に合わせて」と、頭の中で自分から条件を削って小さい版にしてしまっている人が、それを本当に相手へ出す前に、削っていることに自分で気づき、大きい版のまま今日中に出す。

## Central benefit
「無難にする」を自分で選んだ判断だと勘違いしたまま出す前に止め、本当はどこまで欲しいかを一度そのまま文字にしてから出す判断に変える。効用は1つ、これだけに絞る。

## Problem / design rationale
自己を小さく見せる編集は、迷惑・拒否・身の丈違反・目立つこと・失敗の恥・面倒な人認定、という具体的な恐れへの先回り防衛であることが多い。恐れそのものを消そうとすると時間がかかるが、「今回のこの一文をどちらの大きさで出すか」という1回きりの選択に絞れば、恐れを説得しなくても行動だけ変えられる。そこで本アプリは、感情の説明ではなく「小さい版」と「大きい版」を両方実際に書かせ、恐れの正体（6種）ごとに大きい版の作り方の型を渡す。

## Core interaction
1. 今まさに小さくして出そうとしている一文を1行で入力する（小さい版）。
2. それを小さくしている理由に一番近いものを6択から選ぶ。
3. 理由に対応した「拡大の型」で書き換えられた大きい版がテキストエリアに入り、自分の言葉として編集する。
4. 「今日中にこの大きい版でやること」を1行で決める。
5. 3カウントのあとアプリを離れ、現実で大きい版のまま送る・言う・出す。
6. 戻ったら「大きいまま出せた／また小さくして出した」を記録する。小さくして出した場合は、元の小さい版より確実に大きい「半歩だけ大きい版」を3案出し、そこへ再挑戦させる（振り出しの小さい版へは戻さない）。

小さい版と大きい版を両方実際に書いて比較させる操作そのものが、「自分がどれだけ削っているか」を可視化し、大きい版を選び直す反射を鍛える。読ませるのではなく、書かせて比較させることが核。

## First 10 seconds
開くと即座に「今、何を小さくして出そうとしていますか」という一文入力欄が主役として見える。説明文なしで、何を入力すればいいかがプレースホルダー例文（例：予算はいつもどおりで、と頼む）で分かる。

## Success condition
今日中に、最初に入力した小さい版より大きい版のまま、現実で実際に送る・言う・出す・提示することができた（「大きいまま出せた」を記録した状態）。

## Uniqueness
「今やる。」は着手ゼロ→着手への先延ばし解消が対象で、扱う内容の大きさは変えない。本アプリは「すでに着手する気はあるが、内容そのものを自分で値切って小さくしている」状態が対象で、小さい版と大きい版を両方書かせて内容のサイズを直接引き上げる点が異なる。「main-character」は生き方の選択全般を扱う抽象度の高いアプリで、具体的な一文の大小比較という操作は持たない。

## Repeat-use strategy
提案・お願い・目標・値段交渉など、場面ごとに再発する。端末内に「大きいまま出せた率」と「よく縮める理由」を蓄積し、自分がどんな場面で一番自分を値切るかを可視化して、次回の理由選択の精度を上げる。

## Title rationale
- Main user benefit/motive: 目立ちたい／もっと評価されたい／今の自分の頭打ちを抜けたい、という「言いたいことを削らず出したい」欲求。
- Why this title is direct and specific: 「大きく出る」は日本語で「思い切った要求・提案をする」という既存の言い回しであり、新語や比喩ではなく、実際に人が使う言葉をそのまま採用した。
- How it matches the actual app: アプリの操作そのものが「小さい版→大きい版」への書き換えなので、タイトルと体験が一致する。
- Market/uniqueness checks actually performed (if any): 本プロジェクト内の `scripts/playtest-catalog.mjs` の全アプリ名・説明文と重複しないことを確認済み（「大きく」「出る」を含む既存アプリなし）。外部（Google/Amazon等）でのタイトル調査は本タスクの範囲では未実施。
