# 404怪異調査クラブ — ゲーム仕様書 v1.0

通称：**404部**

---

## 0. 本仕様書の目的

『404怪異調査クラブ』を、単なる都市伝説紹介ゲームではなく、

- 「3人で現地を歩き回ること自体が楽しい探索ゲーム」
- 「ふざけていた3人が、本物の怪異を見つけた瞬間に空気が変わるホラー」

として成立させるための実装基準を定義する。

特に重要なのは、説明文や選択肢を読むことではない。

プレイヤー自身が、

**歩く → 見つける → 近づく → 何か起こる → さらに奥へ行く**

という行動を繰り返すことで物語が進むゲームにする。

> **本仕様書の位置づけ**
> この仕様は、旧実装（架空スマートフォンOSを操作する謎解き型）を置き換える新方針である。
> 旧実装は §71「絶対にやらないこと」に該当する構造だったため削除済み。
> 旧コードを参照する場合は `git log -- apps/404-kaiki` から辿る。
>
> 現在 `apps/404-kaiki` には、この仕様に基づく **CASE 01 の5エリア縦切り版**（§58）が
> 実装されている。範囲と実装状況は [`CASE01_SLICE.md`](./CASE01_SLICE.md) を参照。
> Working Planet からの流用（§61 / §72 第1段階）は未実施で、探索部分は新規実装している。

## 1. 正式タイトル

**404怪異調査クラブ**

通称：404部

## 2. ジャンル

スマートフォン向け探索型・都市伝説ホラーアドベンチャー

要素としては、

- フィールド探索
- キャラクター掛け合い
- 都市伝説
- ホラー
- エリア開放
- 逃走
- CASE形式の連続ストーリー

を組み合わせる。

## 3. 一言で表現すると

> ネットで怖い噂を見つける。3人で確かめに行く。本当にいた。全力で逃げる。

これをすべてのCASEの基本体験とする。

## 4. 作品の中心

本作には3つの楽しさがある。

### ① 次の場所を見たい

探索の楽しさ。まだ見えていない路地、建物、教室、ホーム、山道などへ進みたくなる。

### ② 開けたい。でも怖い

ホラーの楽しさ。ドアの向こう、曲がり角の向こう、暗い道の先に何があるかわからない。

### ③ 404部の3人をもっと見たい

キャラクターの楽しさ。怪異だけではなく、3人の会話そのものが作品の魅力になる。

## キャラクター

主人公は中学生3人組。

### 5. 四郎（シロウ）

名前の「四」から **4**。

行動派。考えてから動くというより、「行けば分かるだろ」で進んでしまう。
怪しいドアがあれば一番最初に近づく。怖くないわけではなく、怖い時ほど強がる。

**ゲーム上の役割**

プレイヤーの「先へ行きたい」という感情を代弁する。
停滞しそうな場面では四郎が動くことで、自然に進行を促す。

### 6. 零（レイ）

名前から **0**。

ネット、掲示板、怪談、都市伝説に詳しい。今回調査する噂を持ち込むことが多い。
普段は冷静。ただし本物らしい怪異を見ると、怖がるより先に興味を示すことがある。

**ゲーム上の役割**

怪異に必要な最低限の情報を自然に説明する。
長いチュートリアルではなく、「その噂、似た書き込みが三つある」程度の短い発言で情報を補う。

### 7. 四葉（ヨツバ）

名前の「四」から **4**。

3人の中では比較的常識的。シロウとレイへのツッコミ役になりやすい。
ただし非常に観察力が高い。「何かがおかしい」と最初に気づくことが多い。

**ゲーム上の役割**

怪異や異変の存在を、UIではなくキャラクターの動きでプレイヤーに気づかせる。

例えば、

1. 四葉だけが立ち止まる。
2. 遠くを見る。
3. 「……ねえ。」
4. プレイヤーが画面の奥を見る。
5. そこに何かいる。

### 8. 404部という名前

四郎 = 4 / 零 = 0 / 四葉 = 4

3人を並べると **404** になる。

最初から本人たちが格好つけて命名したわけではない。
学校の同級生が「また404の3人が変な噂調べてる」と呼び始めたことから、**404部** というあだ名が定着する。

正式な学校の部活動ではない。本人たちは途中から面白がって「404怪異調査クラブ」と名乗り始める。

### 9. キャラクター作品としての方向性

常時暗く、重苦しい作品にはしない。日常部分はかなり明るくてよい。

イメージとして重要なのは、

**3人のくだらない会話が続いている最中に、突然本当に怖いものが入ってくること。**

例えば夜道。

> シロウ：「肉まん買って帰ろうぜ」
> レイ：「コンビニは逆方向」
> ヨツバ：「じゃあ帰りにすれば？」
> シロウ：「怪異より肉まんが先だろ」

歩いている。その途中でヨツバだけ止まる。会話が消える。
遠くの街灯の下に、人が立っている。

この温度差を作品の基本演出とする。

## ゲームループと操作

### 10. 基本ゲームループ

1CASEは次の構成とする。

1. **噂を発見** — SNS、掲示板、学校、動画などから怪異の噂を知る
2. **404部で現地へ向かう** — 短い掛け合い
3. **現地探索** — キャラクターを動かしてマップを歩く
4. **調査ポイント発見** — マークへ近づく
5. **自動調査** — タップ不要
6. **新しい場所が開く** — 探索可能範囲が広がる
7. **怪異の兆候** — 音、影、人影、異常
8. **さらに奥へ進む**
9. **怪異が完全に姿を現す**
10. **逃走フェーズ** — 怪異から逃げる
11. **CASE固有の方法で生還**
12. **調査記録更新**
13. **日常へ戻る**
14. **次の噂**

### 11. 操作思想

**「移動」がほぼ唯一の操作。**

404では、ボタンを大量に並べない。基本的なプレイヤー操作は「移動する」だけ。

物を見る。調べる。ドアを開ける。イベントを見る。
それらは基本的に **近づくこと** で発生する。

### 12. 調査ボタンは作らない

画面上に「調べる」というボタンは設けない。

1. 対象物に調査可能マークが付いている
2. そこまで歩いていく
3. 一定距離に入る
4. 自動的にキャラクターが反応する
5. イベント開始

これだけ。

### 13. 調査マーク

調査対象には世界の中にマークを表示する。

例：`◎` `？` `⌕` など。最終的には404独自のアイコンを制作する。

重要なのは、**何が触れるものなのかを一瞬で理解できること。**

マークは、ゴミ箱／ドア／電話ボックス／ポスター／ベンチ／窓／地面の落とし物 など、
実際の対象の位置に表示する。

### 14. 自動調査

1. 調査範囲へ入る
2. プレイヤー操作が一時停止
3. 3人のうち適した人物が対象へ寄る
4. 簡単なアニメーション
5. 1〜3往復程度の会話
6. 必要なら世界が変化
7. 自動で探索状態に戻る

テンポを止めない。

## ガイドライン（緑のライン）

### 15. 緑のガイドライン

Working Planetで使用している「次の目的地へ伸びる緑色のライン」を404でも中核UIとして利用する。

これは非常に重要。プレイヤーに「○○へ行ってください」と説明しない。
緑のラインを見れば、次に進める方向が分かる。

### 16. ガイドラインの挙動

通常探索では、

主人公付近 → 道路 → 目的地点

へ自然につながる。目的地が変わるとラインも更新。調査完了後には、次の目的地へ伸び直す。

### 17. ガイドラインを万能にしない

常に完全な答えを示すわけではない。

| 状況 | 挙動 |
| --- | --- |
| 序盤 | かなり明確 |
| 中盤 | 途中まで |
| 怪異発生直前 | 途切れることがある |
| 完全出現時 | 一度消える |
| 逃走時 | 安全地点が判明している場合のみ、逃走ラインとして復活 |

**ガイドライン自体を演出に使う。**

## マップとエリア

### 18. マップ設計

完成版の1CASEは、**15〜20程度の小エリア** で構成する。

巨大な1枚マップを最初から全部歩かせるのではない。プレイに応じて少しずつ行動範囲が広がる。

### 19. エリアとは何か

「エリア」は画面切り替えとは限らない。

例えば住宅街なら、住宅街入口／公園／商店前／ゴミ置き場／細い路地／団地前／地下道／学校裏／川沿い／神社参道／神社境内 など。

基本的には同じ世界がつながっているように見せる。

### 20. エリア開放

単に `AREA 05 UNLOCKED` とは表示しない。**世界そのものが変わる。**

例えば、

- 開かなかった門が開く
- フェンスの一部が外れる
- シャッターが上がる
- 鍵を持つ人物が移動する
- 暗かった道に電気がつく
- 踏切が開く
- ドアが開く
- 一本道だと思っていた場所に脇道が見つかる

**進行＝画面変化** にする。

### 21. 調査ポイント数

完成版1CASE：**20〜30ポイント程度**。ただしすべて必須にはしない。

- **必須調査** — ストーリー進行に必要
- **任意調査** — 会話、伏線、都市伝説情報、キャラクター描写
- **隠し調査** — 注意深く探索した人だけ見つけられる

### 22. ドア

本作において、**ドアは重要なホラー装置** とする。

マーク付きのドアへ近づく → 3人が少し止まる → ドアノブが動く → 少し遅れて開く。

### 23. ドアの中身

必ず何かが出てはいけない。

結果候補：普通の部屋／誰もいない／証拠／NPC／新エリア／別の出口／暗い廊下／音だけ鳴る／影が横切る／怪異がいる／本当に何もない

**「何もない」があるから、次のドアも怖い。**

## ホラー設計

### 24. ホラーの基本思想

突然大音量を鳴らすだけのジャンプスケアに頼らない。

基本は **「遠くに何かがおかしい」** から始める。

### 25. 怪異出現の5段階

| PHASE | 状態 | 内容 |
| --- | --- | --- |
| **0** | 普通 | 3人がふざけながら探索。怪異らしいものはない |
| **1** | 違和感 | 変な音／街灯が消える／NPCがいなくなる／電話が鳴る／カラスが急に飛ぶ／ドアが勝手に閉じる |
| **2** | 遠景 | 遠くに怪異らしいもの。まだ危害はない。「見間違いかもしれない」という距離感 |
| **3** | 接近 | 曲がり角／窓／路地／反対ホーム／田んぼの向こう。何度か確認できる |
| **4** | 完全出現 | プレイヤーも3人も「本物だ」と理解する。ここから逃走フェーズ |

### 26. 怪異出現位置

怪異をプレイヤーの真横へ突然スポーンさせない。基本的には **少し遠い場所** へ出現させる。

推奨位置：道の奥／数エリア先／窓の中／屋上／反対ホーム／田んぼの中央／橋の向こう側／一本道の端

**プレイヤーが先に発見できる余地を残す。**

### 27. ランダム性

怪異出現には一定のランダム性を持たせる。完全に毎回同じ場所だと恐怖が薄れる。

ただし完全ランダムにはしない。各エリアごとに **怪異出現候補地点** を複数設定し、その中からランダム選択する。

### 28. 3人のリアクションをUIにする

画面中央に `WARNING` などを毎回出さない。代わりにキャラクター自身がヒントになる。

例えば、ヨツバが止まる。レイが後ろを向く。シロウが「何？」と言う。
これでプレイヤーも周囲を見る。

## 逃走フェーズ

### 29. INVESTIGATION → ESCAPE

ゲーム後半ではモードが明確に変化する。

- 前半：**INVESTIGATION**（探索）
- 後半：**ESCAPE**（逃走）

この変化を、音楽／キャラクター速度／カメラ／ライン／ライティング／怪異AI によって明確に伝える。
大きな説明文字には頼りすぎない。

### 30. 戦闘はしない

怪異にHPは設けない。404部は怪異退治の専門家ではない。攻撃ボタンも基本的にない。

怪異が現れたら、**逃げる。**

### 31. 怪異ボックスは廃止

シリーズ共通の捕獲装置は作らない。怪異を箱に閉じ込めるゲームにはしない。

CASEごとに、**その怪異だから成立する逃げ方** を用意する。

### 32. CASEごとの生還条件

毎CASE、終盤のゲームルールを少し変える。

| 例 | 内容 |
| --- | --- |
| 神社へ逃げ込む | 鳥居を越えると怪異が止まる |
| 踏切を越える | 向こう側まで行く |
| 家へ戻る | 特定の家へ逃げる |
| 電車へ乗る | ホームから脱出する |
| 見ない | 怪異を画面内へ入れない状態で移動する |
| 音を出さない | 一定区間を静かに進む |
| 朝まで逃げ切る | 時間経過型 |

### 33. 逃げ方は事前に伏線を張る

**最重要。** 終盤に突然「神社へ行け！」とは言わない。

前半で神社を発見している。

> 四葉：「ここだけ静かだね。」
> レイ：「昔から神社の中には入ってこないって話はある。」
> シロウ：「じゃあ怪異出たらここ集合な。」
> ヨツバ：「出る前提なの？」

この何気ない会話が、後半で意味を持つ。

### 34. 逃走時の緑ライン

安全地点をすでに発見している場合、怪異出現後に一度消えたラインが、**逃走ルートとして再点灯** する。

探索時の緑ラインと同じものが、突然、**命綱** に変わる。

これは本作の代表的な演出にする。

### 35. 捕まった場合

怪異に接触するとゲーム終了ではなく、

短い恐怖演出 → 暗転 → 直前のチェックポイントから再開。

### 36. チェックポイント

CASE最初からやり直しにはしない。

チェックポイント候補：新エリア解放／重要調査完了／怪異完全出現直前／逃走フェーズ開始

**プレイヤーの時間を無駄にしない。**

### 37. 生還後

無事に戻る。そこで大げさな `MISSION COMPLETE` は使わない。

日常へ戻る。翌日の教室。帰り道。404部の部屋。など。

> シロウ：「昨日のやつさ」
> ヨツバ：「もう行かないからね。」
> レイ：「次なんだけど。」
> ヨツバ：「聞いてた？」

そこへ次のCASEにつながる。

## 記録と全体ストーリー

### 38. 怪異は収集しない

怪異そのものを捕獲してコレクションするゲームにはしない。代わりに **404調査記録** を蓄積する。

### 39. 404調査記録

各CASE終了後、調査した内容が記録される。

内容例：CASE名／噂／調査場所／遭遇したもの／発見した証拠／任意調査達成率／3人のメモ／未解決事項

ただしWikipedia的な説明画面にはしない。**404部自身が書いたノートのようにする。**

### 40. 未解決を残す

CASEをクリアしても、全ての謎を説明しない。

例えば、口裂け女から逃げ切った。しかし調査記録の最後には、

> 「じゃあ、最初の目撃写真を撮ったのは誰？」

などが残る。次の怪異と少しずつつながる。

### 41. 全体ストーリー

序盤は、それぞれ独立した都市伝説に見える。
しかし複数CASEを遊ぶと、奇妙な共通点が見え始める。

例えば、同じ落書き／同じ数字／同じ人物／同じ看板／同じ音／同じ場所名／404という記号 など。

### 42. 町全体がつながる

最初は「口裂け女ステージ」「テケテケステージ」のように見える。
しかし進行すると、それらが実は **同じ町の中に存在している** ことが分かる。

最終的には、住宅街／学校／駅／商店街／河川敷／田んぼ／山／神社 などが一つの町としてつながっていく。

### 43. 七不思議構造

物語後半では、町に存在する一連の怪異が **町の七不思議** としてつながっている可能性を提示する。

CASE 01〜06までは既存の有名都市伝説を中心に構成。
CASE 07で、今まで存在を知らなかった最後の怪異にたどり着く。

レイが検索する。結果：

```
404 NOT FOUND
```

ここでタイトルの意味が、名前遊びだけではなかった、という形に発展させられる。

※最終設定はシナリオ制作時に決定。

## グラフィック・音・UI

### 45. グラフィック方針

目指すのは「怖い背景画像の上をキャラクターが歩くだけ」ではない。
**ゲーム空間そのものを面白くする。**

### 46. 画面の奥行き

画面は最低でも、

- **前景** — 電柱、木、フェンス、看板など
- **プレイ層** — 道路、キャラクター、建物、調査対象
- **背景** — 遠くの建物、山、空、電線、街灯

の複数レイヤーを持つ。真上からの平面的なタイルマップだけにしない。

### 47. ランドマーク

各エリアには、遠くからでも分かる特徴を必ず置く。

例えば、赤い鳥居／巨大団地／給水塔／踏切／高架／廃屋／時計塔／駅舎／学校

プレイヤーが「神社の方へ戻ろう」と空間を記憶できるようにする。

### 48. キャラクター表示

3人とも常に小さすぎない。スマートフォン画面でも **誰が誰か一瞬で判別できる** サイズとシルエットにする。

重要な要素：髪型／色面／バッグ／制服の着こなし／立ち方／歩き方 を変える。
**顔の細部だけで区別させない。**

### 49. 3人の移動

基本的には3人一緒に移動。完全に重ねない。

シロウが少し前。レイとヨツバが自然についてくる。狭い道では一列になる。停止時には少しばらける。

これにより **3人で探検している感覚** を出す。

### 50. 会話表示

長いADV画面へ頻繁に切り替えない。基本はフィールド上の吹き出し。
短い会話ならそのまま歩きながら表示。重要なシーンのみ、カメラ寄り・専用演出を使う。

### 51. 音

404では音を非常に重要視する。

環境音：遠くの車／虫／電車／風／電線／犬／踏切／自販機／靴音／ドア

これらの日常音を先に作る。そこから、**日常音がなくなること自体** を恐怖演出に使う。

### 52. 怪異専用BGMを常時流さない

怪異が近いからといって毎回怖いBGMを流すと、存在を教えてしまう。

音楽より、ノイズ／足音／呼吸／遠くの声／不自然な無音 などを使う。

### 53. スマートフォンUI

縦画面を基本候補とする。最終的にはWorking Planet側の既存操作系を確認した上で決定。

表示する常設UIは最小限。候補：CASE番号／一時停止／必要なら簡単な調査記録／移動入力

それ以外は極力ゲーム空間へ統合する。

## 導入体験

### 54. チュートリアル

文章で「緑色の線に沿って移動してください。」とは極力言わない。

最初のCASE開始直後、シロウの前から最初の調査ポイントへ緑ラインが伸びている。
プレイヤーが自然に動く。対象へ触れる。自動でイベントが起こる。

これだけで基本操作を理解させる。

### 55. 初回プレイ30秒

最初の30秒で必ず、

- 3人がいる
- 自分で歩ける
- 緑ラインが見える
- 調査マークがある
- 近づくと何か起きる

を体験させる。長いオープニングを先に置かない。

### 56. 初回プレイ3分

3分以内に最低一度、「ちょっとおかしい」ものを見せる。
最初の怪異完全登場まで長く引っ張りすぎない。ただし怪異本体をすぐ真正面から見せない。

### 57. 1CASEの想定時間

完成版：**15〜20分程度**

| 区間 | 時間 |
| --- | --- |
| 噂・導入 | 1〜2分 |
| 前半探索 | 4分 |
| 中盤探索 | 5分 |
| 怪異接近 | 3分 |
| 逃走 | 2〜4分 |
| エピローグ | 1分 |

## 技術方針

### 61. Working Planetから流用するもの

実装前にWorking Planetの実コードを確認する。

候補：キャラクター移動／タッチ操作／カメラ追従／ワールド座標／オブジェクト配置／建物配置／衝突／NPC追従／経路計算／緑ルート／スクロール／エリア解放／セーブ／認証

実際のモジュール名や流用方法はコード確認後に確定する。

> **未解決（本リポジトリ内での制約）**
> Working Planet は本リポジトリには含まれず、別サイト（`working-planet.hitobito.jp`）として運用されている。
> §72 第1段階（実コード調査）は、Working Planet のソースへアクセスできる状態になってから着手する。
> それまでは流用可否を確定できないため、モジュール名を仮定して実装を始めない。

404には不要。

通貨／売上／生産／商品／店舗経営／資源／運搬／設備投資／経済成長／放置収益

## 完成基準

### 70. 完成判定

コードが動いた段階を完成とはしない。以下を満たすこと。

- [ ] 初見で移動方法が分かる
- [ ] 次の目的地を迷わない
- [ ] 調査可能物が分かる
- [ ] 調査ボタンがなくても操作できる
- [ ] エリアが広がったことが目で分かる
- [ ] キャラクター3人を判別できる
- [ ] 3人の掛け合いが面白い
- [ ] 怪異出現前にも探索自体が楽しい
- [ ] 怪異を遠くから発見できる
- [ ] 怪異出現で空気が変わる
- [ ] 逃げる方向が理解できる
- [ ] 捕まっても理不尽ではない
- [ ] 生還時に達成感がある
- [ ] 次のCASEを見たくなる

### 71. このゲームで絶対にやらないこと

- 文章を読むだけで進むゲームにしない
- 証拠を3つ押して終わるゲームにしない
- 「調べる」ボタンだらけにしない
- 説明UIで全部教えない
- 怪異を突然目の前へ出して驚かせるだけにしない
- 怪異をHPで倒さない
- 共通の怪異捕獲ボックスを作らない
- エリア開放を文字だけで済ませない
- 小さすぎるキャラクターを動かすゲームにしない
- 静止画の背景を切り替えるだけのゲームに戻さない

## 73. 最終的に目指す感覚

プレイヤーが最初に感じるのは、

> 「この3人、なんか好きだな」

次に、

> 「あそこ行けそう」

そして、

> 「あれ……遠くに誰かいない？」

最後には、

> 「やばい、戻れ戻れ戻れ！」

生還後、

> 「次は何を調べに行くんだろう」

と思わせる。これを『404怪異調査クラブ』の完成形とする。
