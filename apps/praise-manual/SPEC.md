# 私の褒め方 取説 — Product Spec

## Exact use moment
パートナー、上司、部下、友人に「自分はどう褒められると嬉しいのか」を伝えたいが、うまく言語化できないときに開く。約90秒・文字入力なしで回答し、そのまま相手へ送れる褒め方の取扱説明書を作る。

## Central benefit
自分に刺さる褒め方を7軸で言語化し、相手が次に褒める瞬間から使える具体的な「3ステップ・例文・NG例」に変える。

## Problem / design rationale
「褒めてほしい」と伝えるだけでは、人前で褒めるか1対1か、結果を見るか努力を見るか、言葉で言うか信頼を行動で示すかなどの好みまでは伝わらない。一方、単なる性格ラベルでは受け取った相手が何をすればよいか分からない。そこで、診断結果を人物評価ではなく「次の褒め方の手順」に変換し、共有先でそのまま使える形にする。％は一般人口との比較ではなく、10問の回答から算出した好みの傾きだと明記する。

## Core interaction
10の具体場面で二択をタップする。回答から以下の7軸を算出する。
- 人前 / 1対1
- 結果 / 努力・工夫
- 短い一言 / 具体的
- 言葉 / 行動・信頼
- あとで / その場で
- 盛大に / 静かに
- 称賛 / 感謝・役立ち

結果では7軸の傾向、タイプ名、3ステップの褒め方レシピ、仕事で使える例文、パートナー・友人向け例文、刺さりにくい褒め方、タイミング・温度・意味の取扱メモを返す。

## First 10 seconds
最初の画面で「私の褒め方 取説」と、人前/1対1・結果/努力・言葉/行動という診断内容を即表示する。「10問で作る」を押すと説明書なしでQ1へ進み、1画面1問・二択だけで操作を理解できる。

## Success condition
ユーザーが10問を最後までタップし、自分の好みを説明できる結果まで到達する。さらに共有URLを相手へ送り、受け取った側が質問回答そのものを見ずに「この人を褒めるなら」という実行可能な取説を読めること。

## Uniqueness
既存の自己理解診断は本人に結果文を返すことが中心だが、このアプリの中心成果物は「本人を理解する説明」ではなく、第三者が使える褒め方の手順書。共有先で具体的な行動に変わることが独自性。

## Repeat-use strategy
日常的な訓練アプリではなく、関係性ごとに再確認・再共有する単発寄りの設計。仕事環境や人間関係が変わったとき、または自分の好みが変わったと感じたときに再診断できる。「最初から」で回答をやり直し、共有された取説からも受取人が自分版を作れるため、利用者間で次の診断へつながる。

## Title rationale
- Main user benefit/motive: 褒められたい / 自分を理解してほしい / 相手に簡単に伝えたい
- Why this title is direct and specific: 「私の褒め方」と「取説」で、何について・誰向けの成果物が出るかを短く表す。
- How it matches the actual app: 結果画面は実際に「私に刺さる褒め方」と7軸・3ステップ・例文・NG例を取扱説明書として表示する。
- Market/uniqueness checks actually performed: タイトル決定では外部市場検索を条件にせず、依頼名と実装内容の一致を優先した。

## Share loop
本人が10問回答 → 取説完成 → URL共有 → 相手が「この人を褒めるなら」を読む → 「自分の『褒め方』取説も作る」から次の診断へ進む。

## Privacy
回答・名前はサーバー保存しない。共有URLには完成した結果のみをエンコードし、各質問への回答そのものは共有画面に表示しない。

## Score interpretation
％は10問への自己回答から算出した「好みの傾き」。一般人口での順位、能力、心理学的な標準化得点ではない。
